# STRATEGY6 Task 2 opening-evaluation audit

## Audit findings

1. `opening_guidance.py` only activates while a side still has at least three undeveloped minor pieces, so it shuts off before the late-opening `Rc1` / `a3` / `a4` drift positions that still need development-first pressure.
2. `opening_development.py` had a penalty gap once only one minor piece remained:
   - `early_flank_pawn_poke_penalty()` no longer charged `a`/`h` pawn drift strongly enough.
   - the earlier STRATEGY6 fix for unsettled `h`-pawn lunges covered `h4`, but not the quieter `a3` / `a4` fallback that replaced the old `Rc1` choice.
3. `evaluation.py` and move ordering were disagreeing in one important remaining baseline case:
   - move ordering already demoted `...Nh6` and shallow search avoided it,
   - but depth-3 search could still surface `...Nh6`, so the remaining fix is now primarily a Task 3 move-order / root-choice problem rather than a missing static penalty.

## Task 2 changes

1. Extended late-opening pawn-drift penalties so unfinished-development positions still punish:
   - `a3` / `a4` style edge-space grabs,
   - `h4` style kingside lunges,
   - decorative rook sidesteps on the home rank.
2. Increased the late-opening rim-knight penalty so evaluation more clearly distinguishes central development from edge development once the opening is partially developed.
3. Kept the new evaluation work inside the shared opening-development helpers and a single combined drift scan so the depth-5 timing guard stayed green.

## Current post-Task-2 probe status

- Early `Rc1` baseline position: depth-3 best move is now `g2g3`
- `h4` baseline position: depth-3 best move remains the healthier `f1g2`
- `...Nh6` baseline position: depth-3 still sometimes chooses `g8h6`, even though ordering and shallow search now demote it
